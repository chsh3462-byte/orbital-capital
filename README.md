# Orbital Capital · 오르빗 캐피탈

아스트라 성계의 독립 우주 기업을 운영하는 한국어 싱글플레이 경영 게임입니다. 함선 3척과 네레이드의 우주 공항으로 시작해, 운송·시설 수입을 연구나 광고에 재투자하거나 경쟁사 주식을 사들일 수 있습니다. 본사 지도에서 행성이나 이름표를 누르면 해당 자산을 관리합니다.

## 실행

[Windows x64 배포본 다운로드](https://github.com/chsh3462-byte/orbital-capital/releases/latest/download/OrbitalCapital-Windows-x64.zip) · [버전별 릴리스](https://github.com/chsh3462-byte/orbital-capital/releases)

ZIP 전체를 압축 해제한 뒤 `OrbitalCapital-win-x64` 폴더에서 `OrbitalCapital.exe`를 실행하세요.

| 용도 | 여는 파일 |
| --- | --- |
| Windows x64 게임 | `dist/OrbitalCapital-win-x64/OrbitalCapital.exe` |
| 소스에서 바로 플레이 | `game/index.html`을 Chrome 또는 Edge에서 열기 |

두 실행 방식 모두 플레이 중 인터넷 연결이 필요 없습니다. Windows 버전은 배포 폴더 전체를 함께 옮겨야 합니다. 브라우저와 Windows 버전은 각각 독립된 저장소를 사용합니다.

## 처음 플레이할 때

첫 화면에서 **인계받기**를 누르면 운항실장 윤서진이 네레이드에서 돌아온 운송장 한 장으로 첫 근무를 안내합니다. 실제 장부에서 출발 거점과 분기 손익을 찾고, 기관실의 워프 견적과 영업팀의 광고 시안을 비교합니다. 이어 후보지 실사, 3주 주문 견적, 잔여 지분 인수 비용, 저장 슬롯까지 여덟 번의 짧은 인계를 진행합니다. 견적은 현재 게임의 운임·시설·연구 상태로 계산하며, 자금 집행은 플레이어가 해당 경영 화면에서 직접 결정합니다.

**자유 경영**을 선택하면 즉시 운영을 시작합니다. 진행 중 **나중에**로 닫은 인계는 왼쪽 **근무 인계서**에서 이어볼 수 있습니다. 확인한 단계는 자동·수동 세이브에 함께 담기고, 끝까지 본 뒤에도 같은 메뉴에서 처음부터 다시 읽을 수 있습니다.

1. **경영 관제실**에서 민트색 본사와 네레이드를 확인합니다. 상단 숫자는 보유 현금, 직전 결산의 순이익, 현재 시장 점유율과 평판입니다. 하단 운영 기록에 매매·개발·결산 결과가 쌓입니다.
2. **행성 개발**에서 미개척 에이르를 매입하고 우주 공항을 건설합니다. 토지만 보유해도 유지비가 발생하고, 시설은 다음 결산부터 매출을 냅니다.
3. **함대 연구소**에서 워프 추진기나 화물칸을 연구해 운송 매출을 높입니다. 광고는 남은 기간 동안만 매출과 평판에 보너스를 줍니다.
4. **증권 · 인수합병**에서 경쟁사의 가격 이력을 보고 수량을 입력해 거래합니다. 인수 검토 창에서 잔여 지분 비용을 확인한 후 확정할 수 있습니다.
5. **게임 저장**으로 지금 시점을 수동 슬롯에 보관합니다. **불러오기**에서 수동·자동 기록의 날짜와 잔액을 비교해 복원합니다.

시작일은 2186년 1월 11일입니다. 앞선 열흘은 같은 경제 엔진으로 정산한 영업 이력입니다. 1배속에서는 3초마다 시세가 바뀌고 네 번의 시세 갱신마다 하루를 결산합니다. 상단에서 일시정지와 1·2·4배속을 선택합니다. 거래 및 건설 창을 열면 시세와 시간이 멈춰 표시된 조건대로 결정할 수 있습니다. 숨긴 창과 종료한 게임의 시간은 진행되지 않습니다.

## 시스템과 회계

**자오선 자유항**은 세 항로가 만나는 중립 환승항입니다. 교역 회랑에는 장신구·공예·미술품과 특산품 16점이, 수평선 격납고에는 비행선 8척이 진열됩니다. 판매처에서 실물과 제작 기록을 확인하고 구입하면 개인 보관고에 인도됩니다. **개인 라운지**에는 인도받은 소장품만 표시됩니다. 직접 유리 전시대·갤러리 벽면·전용 계류장에 배치하거나 다시 보관하고, 장신구는 착용하고 비행선으로는 유람할 수 있습니다.

선급원은 비행선에 연안급(Ⅰ), 순항급(Ⅱ), 원정급(Ⅲ), 대항해급(Ⅳ) 인증을 부여합니다. 전시장은 등급별 두 척을 모아 보여 주며, 유람할 수 있는 목적지가 등급에 따라 3·4·5·6곳으로 늘어납니다. 선급과 목적지는 구입 전 기체 명세에서 확인할 수 있습니다.

**비밀 경매**는 구항의 봉인 중개소에서 초대장을 열어 입장합니다. 위탁 아티팩트 8종이 한 점씩 순환하며, 새 물품을 배정한 뒤 게임 시간으로 사흘 후 개찰합니다. 기관 세 곳의 봉인 가격보다 높은 금액을 써내면 자신의 입찰액에 낙찰됩니다. 동액이면 먼저 접수한 기관이 우선합니다. 입찰액은 즉시 예치되고, 증액 시 차액만 지불합니다. 패찰하면 전액을 돌려받습니다. 경매장을 떠나도 게임 시간이 흐르면 정산됩니다. 소장품으로 인도된 유물은 다음 출품에서 제외됩니다.

**항성간 카지노 황혼선**은 외항에 정박한 독립 여객조합의 선박입니다. 녹색 펠트에 적색·흑색 또는 0~36 중 한 숫자를 선택한 후 500 CR로 목제 룰렛을 돌립니다. 적중 시 색은 총 1,000 CR, 숫자는 총 18,000 CR를 받습니다. 0은 녹색입니다. 지급액에는 판돈이 포함됩니다. 황혼선에서는 블랙잭(히트·스탠드), 바카라(푼토 방코), 크라운 앤 앵커(문양 주사위 세 개)도 각각 500 CR로 즐길 수 있습니다. 블랙잭을 도중에 닫거나 게임을 종료하면 이미 받은 카드와 남은 덱을 저장합니다. 소장품 대금, 입찰 예치금, 룰렛 손익은 가용 자금에 즉시 반영됩니다. 기존 세이브의 소장품·전시·착용과 이전 카지노 기록을 보존하며, 진행 중인 경매와 룰렛 결과도 저장합니다.

게임 상태는 일반 객체입니다. 렌더러에는 상태를 읽기 전용으로 전달하고, 현금이나 소유권 변경은 경제 모듈의 명령을 통합니다. 경제 진행은 화면 프레임 수와 독립적입니다. 예를 들어 시세 한 틱이 일일 마감까지 도달하면 `step`이 그날의 재무 행을 반환합니다.

```js
const state = Economy.newGame();
Economy.research(state, "warp");
Economy.advertise(state, "holo");
const settlement = Economy.step(state);
if (settlement) console.log(settlement.net);
```

기술의 가격·설명은 `data.js`의 `techs`, 실제 효과와 결산식은 `economy.js`의 `forecast`, 지도 속도는 `renderer.js`의 `StarMap.draw`에서 조정합니다. 효과 수치를 바꿀 때는 대응하는 화면 설명도 함께 수정합니다.

## 내 픽셀 아트 연결

기본 자산은 **가로 한 줄의 4프레임 PNG 시트 52종**입니다. 우주선은 우측을 향하는 48×32 프레임, 본사는 116×100, 일반 행성은 64×64, 고리 행성은 84×64, 시설·홀로그램은 48×48, 라운지 소장품은 64×48, 주식·광고·칩·토지·크레딧 아이콘은 32×32입니다. 지도용 이미지의 배경은 투명하며, 함선 3티어는 검은 배경의 `ship1-black.png` ~ `ship3-black.png`도 제공합니다.

예를 들어 직접 그린 함선의 프레임 한 장이 48×32라면, 4장을 왼쪽부터 나란히 붙여 192×32 PNG로 저장합니다. 각 칸의 기체 중심과 그림 여백을 맞추면 엔진만 깜박이고 선체가 흔들리지 않습니다.

1. 파일을 `game/assets/my-freighter.png`로 복사합니다.
2. `game/assets/sprites.js`의 기존 `ship1` 항목을 아래 값으로 바꿉니다. 경로 기준은 `game/index.html`입니다.

```js
"ship1": {
  "src": "assets/my-freighter.png",
  "w": 48,
  "h": 32,
  "frames": 4,
  "fps": 8
}
```

3. `game/index.html`을 다시 열어 관제실의 항로와 함대 현황에서 확인합니다. 8 fps이면 한 프레임은 125ms, 한 주기는 0.5초입니다. 같은 방식으로 `hq`, `hologram`, `spaceport`, `chip`을 교체할 수 있습니다. 새 시트를 데스크톱 실행 파일에 반영할 때는 다시 빌드합니다.

아래 예제는 실제 프레임 선택과 같은 방식으로 단일 캔버스에 2배 확대해 그립니다. `imageSmoothingEnabled`는 캔버스 내부 확대를 제어하고, CSS `image-rendering`은 표시 영역의 확대를 제어합니다. 프레임 사이에 패딩이 있는 원본은 먼저 패딩을 제거하거나 소스 좌표에 간격을 더합니다.

```js
const canvas = document.createElement("canvas");
canvas.width = 96;
canvas.height = 64;
canvas.style.imageRendering = "pixelated";
document.body.append(canvas);
const ctx = canvas.getContext("2d");
const spec = window.SPRITES.ship1;
const image = new Image();
image.onload = () => {
  const started = performance.now();
  function paint(now) {
    const seconds = (now - started) / 1000;
    const frame = Math.floor(seconds * spec.fps) % spec.frames;
    ctx.imageSmoothingEnabled = false;
    ctx.clearRect(0, 0, canvas.width, canvas.height);
    ctx.drawImage(image,
      frame * spec.w, 0, spec.w, spec.h,
      0, 0, spec.w * 2, spec.h * 2);
    requestAnimationFrame(paint);
  }
  requestAnimationFrame(paint);
};
image.src = spec.src;
```

게임 안에서 이미 로드한 시트는 `PixelArt.sprite(ctx, "ship1", centerX, centerY, width, gameSeconds)`로 그립니다. 카드에 아이콘을 추가하는 예는 `PixelArt.thumb("chip", 32)`입니다. 이 함수가 반환한 캔버스 HTML을 화면에 넣으면 공용 애니메이션 루프가 재생합니다. 기본 아트 생성기 `node tools/make-sprites.cjs`는 기본 PNG와 매니페스트를 다시 쓰므로 직접 그린 원본과 수정한 매니페스트는 별도 보관합니다.

## 저장과 검증

자동 슬롯은 자산 거래, 연구, 광고, 일일 결산 및 게임 종료 시 갱신합니다. 세이브에는 현금, 기본 평판, 연구, 진행 중인 광고·경제 이벤트, 주가 이력, 매입 원가와 보유량, 경쟁사 상태, 합병 이력, 행성 소유권·시설, 당일 비용, 일일·분기 결산과 난수 상태가 포함됩니다. 손상된 자동 파일은 보존하고 수동 슬롯에서 복구하거나 불러오기 창에서 자동 저장을 재개할 수 있습니다. Windows 경로와 Steam Auto-Cloud 설정은 [배포 가이드](RELEASE.md)에 있습니다.

Node.js가 설치된 개발 환경에서 다음 명령으로 회귀 검증을 실행합니다.

```powershell
node tools/check-game.cjs
```

검증기는 손실이 발생한 날의 이중 지출 방지, 배당과 매도 원가, 두 가지 인수 방식, 시설 중복 방지, 광고 만료, 분기 합계, 자금 부족 시 상태 보존을 검사합니다. 저장·복원한 두 상태에 같은 360틱을 진행해 결과가 일치하는지도 확인합니다.
